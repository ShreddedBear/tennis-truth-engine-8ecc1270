16. CONFIRMED TSE-ONLY LIVE-SCORE CORRELATION

==================================================

This was the most recent forensic finding.

TSE’s:

TtlCache

utility itself is byte-identical to State C.

NO ACTION REQUIRED for the utility.

However, the following TSE functionality is completely absent from State C:

* fixtureMetaCache
* getLiveScoresByIdentity
* corresponding ApiTennisProvider implementation
* dedicated regression test:
    compositeProvider.liveScoresIdentity.test.ts

The feature was traced completely.

Mechanism:

When fixtures are listed:

date + player names are cached under the fixture ID for approximately 8 hours.

Later, if a live-score request uses an ID that is not natively API-Tennis’s own ID, the system can recover the fixture by:

date + player names

against API-Tennis’s live window.

Therefore a fixture originally supplied by another provider can still obtain a live score from API Tennis.

Without this functionality:

State C can silently return no live score for some cross-provider fixtures.

Classification:

MUST TRANSFER.

Risk:

MEDIUM if left unreconciled.

The State C Live Tennis namespace uses ID prefixes, while this system uses date/name correlation, so they appear structurally orthogonal.

However, the combined system has never been tested together.
